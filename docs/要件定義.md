# Pokemon Master 要件定義書

## 1. プロジェクト概要

### 1.1 アプリ名
- 記入：Pokemon Master

### 1.2 開発目的
- このアプリを作る目的：
  - 捕まえたポケモンのデータをまとめるため
  - ポケモン図鑑機能  
  - パーティ登録
- ユーザーに提供したい価値：
  - 捕まえたポケモンの把握ができる
  - 捕まえたポケモンの絞り込み検索ができる
  - 捕まえたポケモンのタイプ相性がわかる
  - すべてのポケモンを検索できる
  - パーティーを登録できる
- ポートフォリオとして伝えたいこと：
  - すべてのコードをAIを使用せず、自分で考え実装
  - Web,API,DBすべて作成
  - 外部APIとの連携

### 1.3 開発期間
- 開発開始日：2026.9.22
- 開発終了予定日：2026.11.30

### 1.4 開発対象範囲
- 今回の開発で対象にする範囲：
  - Web
  - API
  - DB
- 今回の開発で対象外にする範囲：
  -ポケモン情報（PokemonApiから取得）

---

## 2. 対象ユーザー

### 2.1 想定ユーザー
- どのような人が利用するか：
  - ポケモンのゲームをプレイしている人

### 2.2 ユーザーの目的
- ユーザーがこのアプリを使って達成したいこと：
  - 捕まえたポケモンの育成状況の把握ができる
  - 捕まえたポケモンのタイプ相性がわかる
  - すべてのポケモンを検索できる

### 2.3 利用シーン
- どのような場面で利用するか：
  - 戦闘時
  - 新しいポケモンを捕まえたとき
  - 捕まえたポケモンのレベルが上がったとき

## 7. データ要件

> アプリ内で扱う情報と、保存する情報を整理します。

### 7.1 扱うデータ
- どのようなデータを扱うか：
  - ポケモンのデータ
  - 捕まえたポケモンのデータ
  - パーティ登録したポケモン

### 7.2 保存するデータ
- PostgreSQLに保存するデータ：
  - 捕まえたポケモンのデータ
  - パーティ登録したポケモン

### 7.3 保存しないデータ
- 毎回外部APIなどから取得するデータ：
  - ポケモン図鑑のデータ

### 7.4 データの更新方針
- いつ登録するか：
  - ユーザーがポケモンボックス（またはパーティ一覧）の追加・編集ボタン押す
  - 各項目を入力し、保存ボタンを押したとき
- いつ更新するか：
  - ユーザーがポケモンボックス（またはパーティ一覧）の編集ボタンを押す
  - 各項目を入力し保存ボタンを押す
- いつ削除するか：
  - ユーザーがポケモンボックス（またはパーティ一覧）の編集ボタンを押す
  - リセットボタンを押し、保存ボタンを押したとき

### 7.5 データ間の関係
- どのデータ同士に関係があるか：
  - 「捕まえたポケモン」と「パーティ一覧」

## 9. API要件（Frontend ⇔ Backend）

> この段階では詳細設計ではなく、どのようなAPIが必要かを整理します。

### API 1
- APIの目的：
  - ポケモンを検索する
- 呼び出す画面・機能：
  - ポケモン図鑑
  - ポケモンを検索する
- HTTPメソッド：
  - GET
- URLの役割：
  ポケモンの情報を取得するため
- Requestで送る情報：
  - 検索した名前
  - 検索した図鑑番号
  - 選択したタイプ
- Responseで返す情報：
  - 画像
  - 名前
  - 図鑑番号
  - タイプ
- 成功時の状態：
  - 必要な情報をFrontendへ返す
- エラー時の状態：
  - エラー情報をFrontendへ返す

  - プログラムの不具合

  - エラー情報を返す

- 想定するケース：
  - データを保存できない

- ユーザーへの表示方法：
  - 見つかりません
  - 保存できません
